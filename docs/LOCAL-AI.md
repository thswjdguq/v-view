# PC의 GPT 키로 실행하기

2026-11-11 사용자 요청에 따라 현재 실행 방식은 **클라우드 배포 없는 개인 PC 모드**다. Firebase 로그인·서비스 계정·Secret Manager·Cloud Run은 필요하지 않다. GPT 요청 자체는 인터넷을 통해 OpenAI API를 사용하므로 API 사용량에 따른 비용이 발생한다.

앱 → USB/에뮬레이터 → PC의 로컬 프로세스 → OpenAI 순서로 요청한다. GPT 키는 `server/.env.local`에만 두며 앱·APK·Git에 넣지 않는다. PC 프로세스는 `127.0.0.1`에서만 수신한다.

## 1. PC에서 실행

PowerShell 첫 번째 창에서:

```powershell
cd C:\v-view\server
npm run local:setup
npm start
```

`local:setup`은 기존 프로젝트의 `server/.env` 또는 `v_view/.env`에서 유효한 형식의 `OPENAI_API_KEY`만 새 PC 전용 설정으로 옮긴다. 다른 설정은 복사하지 않으며 기존 `.env.local`도 덮어쓰지 않는다. 값을 출력하지 않는다. 키가 없으면 만든 `server/.env.local`에 직접 입력하고 다시 실행한다. 키를 채팅에 보내지 않는다.

```dotenv
OPENAI_API_KEY=여기에_실제_GPT_API_키
PORT=8080
```

`v-view local AI: http://127.0.0.1:8080` 안내가 나오면 이 창을 켜 둔다. 이 환경에서는 기존 키 설정을 준비하고 실제 요청을 확인했다. API 키를 바꿨다면 프로세스를 종료하고 다시 실행한다.

## 2. Android 앱 실행

에뮬레이터를 켜거나 USB 디버깅을 허용한 Android 휴대폰을 연결한다. 두 번째 PowerShell 창에서:

```powershell
cd C:\v-view
.\scripts\Run-LocalAndroid.ps1
```

스크립트는 PC 상태 확인 → 기기 선택 → USB 포트 연결 → `main_local.dart` 실행을 수행한다. 기기가 여러 대면 `-DeviceId emulator-5556`처럼 지정한다. 기존 개발 환경의 에뮬레이터에서 검은 화면이 나타나면 `-SoftwareRendering` 옵션을 추가한다. PowerShell 실행 정책 때문에 스크립트를 실행할 수 없으면 아래 수동 명령을 사용한다. 정책을 바꾸지 않아도 된다.

```powershell
adb reverse tcp:8080 tcp:8080
cd C:\v-view\v_view
flutter run -t lib/main_local.dart
```

포트 변경 시 `.env.local`의 `PORT`와 `Run-LocalAndroid.ps1 -Port 8090` 값을 맞춘다. 수동 실행에서는 `adb reverse` 포트와 `--dart-define=LOCAL_AI_URL=http://127.0.0.1:8090/v1`도 맞춘다.

기본 `flutter run`과 `main.dart`도 로컬 진입점을 사용한다. 로그인 없이 홈에서 시작하며 샘플 질문이나 가상 리포트를 자동으로 넣지 않는다. 입력한 지원 정보로 실제 질문을 만들고, 마이크로 인식한 답변을 확인·수정한 뒤 평가한다. 카메라·마이크는 샘플 모드처럼 끄지 않는다. 기록은 기기의 `local_ai` 하위 저장소를 사용해 기존 앱·데모 기록과 분리한다. 기존 Firebase 진입점은 `main_firebase.dart`에 보관했다.

## 설치 파일만 사용하는 경우

`v_view/build/app/outputs/flutter-apk/v-view-local-ai-debug.apk`가 로컬 전용 설치 파일이다. PC에서 `npm start`를 실행하고 연결한 Android 기기에 `adb reverse tcp:8080 tcp:8080`를 적용한 상태로 앱을 연다. USB를 다시 연결하거나 기기를 재시작하면 포트 연결을 다시 해야 할 수 있다. PC가 꺼져 있거나 로컬 프로세스를 종료하면 새 AI 요청은 사용할 수 없다.

APK 재생성:

```powershell
cd C:\v-view\v_view
flutter build apk --debug -t lib/main_local.dart
Copy-Item build/app/outputs/flutter-apk/app-debug.apk build/app/outputs/flutter-apk/v-view-local-ai-debug.apk
```

로컬 HTTP 연결은 Android **디버그** 빌드에서 localhost·127.0.0.1·에뮬레이터 PC 주소만 허용한다. iOS·Flutter Web·일반 네트워크 주소를 통한 공유 서비스는 이번 로컬 경로의 대상이 아니다. 앱에 키를 넣어 릴리즈 배포하는 방식으로 바꾸지 않는다.

## 연결 문제

| 상황 | 확인 |
|---|---|
| PC 연결 실패 | 첫 번째 창의 `npm start`, USB 디버깅 승인, `adb reverse` 재실행 |
| 포트 사용 중 | 이미 실행 중인 v-view 프로세스인지 확인. 다른 프로그램을 임의 종료하지 않고 포트 변경 |
| GPT 키 오류 | PC `.env.local`의 키와 프로젝트 API 권한 확인 후 재시작 |
| 요청 한도 | PC당 시간당 30회·동시 2회와 OpenAI 계정 사용 한도 확인 |
| 마이크 인식 불가 | Android 한국어 음성 인식 서비스·인터넷·마이크 권한 확인. 텍스트 입력도 가능 |
| 저장 실패 | 생성한 답변·피드백을 복사하거나 같은 기록에 저장만 다시 시도 |

`/health`는 PC 프로세스 상태만 확인하며 GPT 키의 실제 유효성·잔여 사용량 확인이 아니다. 웹 페이지의 Origin·외부 Host·비로컬 접속은 차단하고 LAN이나 인터넷에 공개하지 않는다. API 키·토큰·요청 본문을 로그에 출력하지 않는다.

## 확인한 범위

가상 지원 정보로 앱의 실제 요청 코드 → PC → OpenAI에서 질문 생성·꼬리질문·근거 포함 피드백을 확인했다. [실제 응답 자료](verification/v-view-local-ai-live-2026-11-11.json)는 가상 지원자 입력으로 받은 API 응답이며 실제 사용자 성과가 아니다. 휴대폰 마이크 정확도·시선 정확도·iOS는 별도 검증이 필요하다. 세부 실행 결과는 [검증 기록](verification/README.md)을 따른다.

키를 앱에 노출하지 않고 환경 설정에서 읽는 방식은 [OpenAI 공식 인증 안내](https://developers.openai.com/api/reference/overview)를 따른다.

## 현재 앱 사용 순서 (2026-11-17)

1. 홈의 PC 연결 상태를 확인하고 ‘면접 시작하기’를 누른다. 연결 확인은 `/health`만 사용하며 API 키 유효성·잔여 한도까지 검사하지 않는다.
2. 직무·회사와 자료를 입력한다. 이름 필드는 없으며 나이·학력·자격증은 선택이다. 이력서 요약 또는 자소서 질문·답변 1·2·3 중 답변 하나 이상을 작성한다. 실제 자소서 문항으로 제목을 수정할 수 있다.
3. ‘설정 확인하기’ → ‘면접 시작’을 누르면 준비 후 첫 질문으로 들어간다. 앞으로 나올 질문 목록은 미리 보여주지 않는다.
4. 마이크로 답변하고 인식된 텍스트를 확인·수정해 제출한다. AI는 필요한 확인·근거 질문만 판단하며, 추가 질문 화면에서 기본 질문으로 넘어갈 수도 있다.
5. 연습 후 리포트·기록을 확인한다. 미평가 기록에는 평가 재시도, 저장 기록에는 같은 질문 재연습을 제공한다.

지원 자료는 다음 연습에 재사용한다. 설정의 ‘입력 내용 초기화’는 이 자료를 지우고 저장 리포트는 유지한다. 이름 필드가 없더라도 본문에 붙여넣은 이름·연락처가 자동 제거되지는 않으므로 불필요한 개인정보를 제외한다. 지원 자료와 답변은 AI 요청 시 OpenAI로 전송된다.

작성 중 답변·남은 시간은 임시 저장하며 홈의 ‘연습 이어하기’로 일시정지 상태에서 복구한다. 마지막 입력·시간 변경의 지연 저장 구간, 저장되지 않은 AI 결과와 원본 시선 프레임까지 강제 종료 후 보장하지 않는다. 저장 오류가 보이면 종료 전에 답변을 보관하거나 저장을 재시도한다.

## 학교·자격증 검색과 연습 속도 (2026-11-19)

학교는 ‘학교 검색·추가’에서 고른다. 전공·졸업 상태는 학력에 별도로 적는다. 자격증 검색에 ‘정보’를 입력하면 정보처리기사·산업기사·기능사 등 후보를 구분해 표시한다. 여러 항목을 체크한 뒤 ‘선택 완료’를 누르면 입력 화면의 칩으로 반영된다. 칩의 삭제 버튼으로 개별 제거한다. 검색 화면을 뒤로 닫으면 선택 변경은 저장하지 않는다.

검색은 기기에 포함한 기본 목록에서 수행해 검색어를 외부에 전송하지 않는다. 약칭·띄어쓰기 검색을 지원하고 목록에 없는 자격·국내외 학교는 직접 추가한다. 기본 자격 목록에는 과거 명칭도 있으므로 취득한 증서의 정확한 이름을 고른다. 자료 출처와 기준일은 [목록 안내](../v_view/assets/catalogs/SOURCES.md)에 있다. 학교와 여러 자격의 배열은 일반 저장·진행 중 면접 복구·AI 질문 생성으로 함께 전달된다. 기존 문자열 자격 입력도 읽는다.

질문별 준비 시간을 ‘없음·15초·30초’로 선택할 수 있다. 준비 중에는 답변 시간이 줄지 않으며 ‘바로 답변 시작’으로 기다림을 끝낼 수 있다. 답변 시간 종료 시 마이크를 멈추고 인식 텍스트를 보존하며 자동 제출하지 않는다. 답변을 확인해 제출하거나 ‘30초 더 답변하기’를 누른다. 빈 답변은 다음 질문 이동 전에 확인한다.

‘카메라·시선 분석 사용’을 끄면 카메라를 호출하지 않고 텍스트·마이크로 연습한다. 리포트에서는 시선을 점수 0으로 해석하지 않고 끄고 연습했다는 미측정 사유를 표시한다. 준비·일시정지·AI 대기 시간은 시선 측정 구간에 합산하지 않으며, 재개 뒤 늦게 도착한 이전 프레임은 제외한다.
